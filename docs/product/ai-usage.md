# Использование ИИ

Статус: **принято для MVP**. ТЗ: ИИ приветствуется, если создает понятную ценность и не заменяет работоспособность основного сценария; допускаются только модели с открытыми весами. Наше решение: **основной сценарий полностью детерминированный и работает без ИИ; ИИ является опциональным модулем (приоритет Could) на локальной open-weight модели через Ollama, включаемым профилем `ai` в docker compose.**

## 1. Принципы

1. **ИИ не принимает и не меняет кредитных решений.** Скоринг, политика, контрпредложения, коды причин и статусы рассчитываются только детерминированно и воспроизводимо (версии конфигов в каждом решении). Решение, которое нельзя объяснить правилом, противоречит требованию ТЗ разделять скоринг и решение и регуляторной логике объяснения отказов.
2. **Любая ИИ-функция имеет детерминированный фолбэк**, который выдает полезный результат без модели. Если модель выключена, не отвечает за 10 сек или вернула ошибку, пользователь получает шаблонный результат, а не ошибку.
3. **Числа не генерируются моделью.** Суммы, ставки, платежи, даты подставляются в текст после генерации из данных системы; модель работает с формулировками.
4. **Результат ИИ всегда помечен** ("Сформировано автоматически, проверьте по данным карточки") и не сохраняется как часть решения.
5. **Минимизация данных.** На вход модели передаются только структурированные поля без ФИО, ИНН, номеров документов; модель локальная, данные не покидают контур.
6. **Свободный текст клиента считается недоверенными данными** (`client_comment`, текстовые ответы на дозапрос): он либо не передается в модель, либо передается как цитируемые данные с инструкцией не исполнять указания из него; результат все равно проверяет человек.

## 2. Где ИИ создает ценность и где нет

| Идея | Ценность | Решение для MVP | Почему |
|---|---|---|---|
| Резюме заявки для андеррайтера: ключевые риски, расхождения, что уточнить (H14) | реальная на сложных заявках: быстрее войти в контекст | **Could**, профиль `ai`; фолбэк: шаблонное резюме | карточка содержит много данных; резюме не влияет на решение, его проверяет специалист |
| Пояснение условий и решения простым языком (H13) | средняя: шаблоны по кодам причин дают большую часть эффекта | **основа: шаблоны** (Must, детерминированно); ИИ-переформулировка "Объяснить проще" Could | тексты для клиента уже написаны в справочнике причин и подсказках терминов |
| Подбор продукта по свободному описанию задачи | низкая: 8 кнопок-целей решают задачу дешевле и надежнее | **не делаем**, подбор по таблице правил | детерминированность и объяснимость подбора |
| ИИ в кредитном решении или скоринге | отрицательная | **не делаем** | непрозрачно, невоспроизводимо, нарушает разделение скоринга и политики |
| Чат-бот "задайте вопрос" | низкая без проверенной базы знаний, риск неверных обещаний об условиях | **не делаем** | неверный ответ об условиях кредита хуже отсутствия ответа |
| Распознавание документов (H15) | реальная в промышленной эксплуатации | **не делаем в MVP** (ICE 50) | дорого, нужен датасет; без распознавания документ проверяет специалист (допущение A-30) |
| Генерация текста дозапроса андеррайтеру | низкая: шаблоны `NI_*` уже структурированы | **не делаем** | структурированный дозапрос (H5) важнее свободного текста |

## 3. Что делаем детерминированно

| Функция | Как |
|---|---|
| Подбор продукта | таблица правил по цели, сумме, сроку, типу и возрасту бизнеса ([product-catalog.md](product-catalog.md), раздел 4) |
| Калькулятор платежа | аннуитетная формула в `Decimal` |
| Проверка полноты | правила обязательности по продукту |
| Скоринг | балльная карта из версионируемого JSON |
| Решение | упорядоченные правила политики POL-01...POL-07 |
| Контрпредложение | расчет по допустимому платежу и обратной аннуитетной формуле |
| Тексты для клиента | справочник кодов причин и клиентских статусов с подстановками |
| Шаблонное резюме для андеррайтера (фолбэк) | сборка из полей: продукт и сумма; грейд и 3 фактора с наибольшим отрицательным вкладом; сработавшие правила и причины `MR_*`; расхождения анкеты и источников; рекомендация политики; открытые вопросы (неотвеченные пункты дозапроса) |

## 4. Опциональный модуль ИИ

| Параметр | Значение |
|---|---|
| Запуск | профиль docker compose `ai`: сервис Ollama с заранее загружаемой моделью; без профиля сервис не стартует, функции работают на шаблонах |
| Модель | компактная instruct-модель с открытыми весами и поддержкой русского языка, помещающаяся в память обычного ПК (класс 3-8 млрд параметров, квантизация); конкретную модель и ее лицензию выбирает техлид и указывает в THIRD_PARTY_NOTICES |
| Интеграция | API вызывает Ollama по HTTP с таймаутом 10 сек; переменная окружения `AI_ENABLED` и адрес сервиса; при ошибке используется фолбэк |
| Функции | `AI_UNDERWRITER_SUMMARY` (кнопка в BK-03), `AI_PLAIN_EXPLANATION` (кнопка "Объяснить проще" в CL-11) |
| Вход резюме | JSON со структурированными полями: продукт, сумма, срок, цель, отрасль, возраст бизнеса, грейд и вклад факторов, сработавшие правила, расхождения, рекомендация, статус дозапросов; без ПДн |
| Выход резюме | 3 блока по 1-3 пункта: "Ключевые риски", "Что проверить", "Что говорит в пользу" |
| Вход пояснения | шаблонный текст причины или условий; числа заменены метками и подставляются после генерации |
| Журнал | событие `AI_SUMMARY_GENERATED` (модель, латентность, был ли фолбэк), без текста ответа и входных данных |

## 5. Как поймем, что ИИ полезен

| Гипотеза | Метрика | Как проверяем |
|---|---|---|
| H14 | медианное время ручного решения с резюме и без | юзабилити-тест с андеррайтером на одинаковых синтетических заявках |
| H13 | доля участников, верно пересказавших условия и причину, с "Объяснить проще" и без | юзабилити-тест с клиентами по гайду исследования |

Если эффект не подтверждается, модуль остается выключенным: продукт ничего не теряет.
