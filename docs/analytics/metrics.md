# Метрики экрана риск-менеджера (BK-06)

Статус: **принято для реализации**. Формулы переводят дерево метрик исследования ([07-metrics.md](../research/07-metrics.md)) и таблицу [events.md](../process/events.md), раздел 3, в точные определения: что считается, по каким событиям, числитель, знаменатель, окно. Эталонный расчет: `analytics/src/metrics.py` (бэкенд реализует те же формулы в SQL по журналу событий).

## 1. Общие правила

1. **Источник.** Только журнал событий (`event`): метрики воспроизводимы и не зависят от текущего состояния заявки.
2. **Когорта заявок.** Если не сказано иное, заявка относится к периоду по времени `APPLICATION_CREATED`. Это когортный подход: заявка, созданная в периоде, учитывается со всеми своими последующими событиями, даже если они после конца периода. Для текущего месяца значения неокончательные, на экране помечаются "период не завершен".
3. **Окна.** Фильтр периода на экране: 7, 30, 90 дней и произвольный; по умолчанию 30 дней. Фильтр по продукту: по `product_code` из `APPLICATION_CREATED`.
4. **Итоговое решение** заявки: первое событие `DECISION_MADE` с `outcome` в (`APPROVED`, `COUNTER_OFFER`, `DECLINED`). `NEEDS_INFO` и `MANUAL_REVIEW` промежуточные. Последующие решения (например, после возврата риск-менеджером) не меняют "первое итоговое" для метрик скорости, но учитываются в доле переопределений.
5. **Медианы** вместо средних для длительностей: распределения с длинным хвостом (ожидание клиента).
6. **Пустой знаменатель:** метрика не показывается, выводится "недостаточно данных".
7. **SLA North Star** из конфига политики: `decision_sla_auto_minutes` = 15 для решения `mode = AUTO`, `decision_sla_manual_hours` = 24 (1 рабочий день упрощенно) для `mode = MANUAL`.

## 2. Клиентская воронка

| Метрика | Числитель | Знаменатель | Примечание |

| Ожидаемые потери выданных | сумма `pd_by_grade[grade] x LGD x amount` по `LOAN_ISSUED` | | LGD 0,6 (без залога) и 0,4 (инвестиционный с залогом), допущение |
