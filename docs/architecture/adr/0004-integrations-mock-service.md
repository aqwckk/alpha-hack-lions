# ADR-0004. Внешние системы как отдельный сервис-симулятор

Статус: принято. Дата: 2026-10-23.

## Контекст

Реальные ЕГРЮЛ/ЕГРИП, ФНС, ГИР БО, БКИ, данные банка, ЭДО и АБС недоступны (ТЗ: только синтетика и моки). При этом нужно показать надежность: таймауты, ошибки 5xx, повторы, статус ожидания, ручной повтор, идемпотентность выдачи.

## Решение

Отдельный FastAPI-сервис `services/integrations-mock` в той же сети compose:

* источники отвечают по HTTP в конверте `{request_id, source, inn, as_of, data}`, ошибки в формате `{error: {code, message, request_id}}`; `404 NOT_FOUND` означает "нет данных" и считается успешным ответом; неверный ИНН `400`;
* данные: 12 демо-компаний из `analytics/artifacts/demo_companies.json` (дата регистрации пересчитывается от текущей даты) и генератор `analytics/src/mockgen.py` для любого другого корректного ИНН (код импортируется как есть, не переписывается);
* БКИ отвечает только при переданной ссылке на действующее согласие (`403 CONSENT_REQUIRED`);
* поведение сбоев: `mock_behavior` профиля (S5: таймаут на первые 4 запроса), глобальное отключение источника, сброс счетчиков (`/admin/*`, из API через `/api/v1/demo/integrations/*`), задержки через переменные окружения;
* ЭДО формирует пакет документов с sha256 и регистрирует подпись по хешам; АБС выдает кредит или открывает лимит идемпотентно по ключу (тот же ключ с другим телом `409`).

## Последствия

* Код конвейера работает с настоящими сетевыми сбоями и таймаутами; замена на реальные интеграции ограничена модулем `app/services/integrations.py`.
* Состояние симулятора в памяти: перезапуск сбрасывает счетчики и журнал операций АБС; от двойной выдачи защищает и уникальность `loans.application_id` в банке.
* Сервис доступен только внутри сети compose, наружу не публикуется; есть необязательный внутренний ключ `INTEGRATIONS_API_KEY`.
