# ADR-0003. Скоринг и политика как версионируемые конфиги аналитика

Статус: принято. Дата: 2026-10-23.

## Контекст

ТЗ требует различать оценку риска и кредитное решение. Аналитик готовит балльную карту и политику в `analytics/` (с ML-инструментами только во время разработки), бэкенд должен считать в рантайме без ML-библиотек, воспроизводимо и объяснимо, с версией в каждом решении.

## Решение

* `analytics/artifacts/scorecard.v1.json` и `policy.v1.json` копируются в образ при сборке (контекст сборки: корень репозитория), копий в `services/` нет.
* При старте api и воркер проверяют схему (`schema`, `schema_version`), версию и sha256 файла против `SCORECARD_EXPECTED_*` и `POLICY_EXPECTED_*`, базовую структуру (покрытие бинов, правила POL-01...POL-07 по порядку). Ошибка: readiness 503, задачи `SCORE`/`DECIDE` переводят заявку в `PROCESSING_ERROR` с `CONFIG_LOAD_FAILED`, ложного отказа не бывает.
* Расчет на `Decimal` (точность 28, `ROUND_HALF_UP`) в `app/domain/scoring.py` и `app/domain/policy.py` по алгоритму `analytics/artifacts/README.md`, раздел 4.1; параметры, порядок причин ручного рассмотрения и шаблоны дозапроса берутся из конфига.
* Каждый результат скоринга хранит версию и sha256 карты и полный вход расчета, каждое решение хранит версии карты и политики, sha256 политики, путь правил и промежуточные значения. Загрузка фиксируется событием `CONFIG_VERSION_LOADED` и таблицей `config_versions` (экран версий риск-менеджера).
* Один параметризованный golden-тест по `expected_outcomes.json` (63 случая) сравнивает балл, грейд, PD, баллы факторов, значения признаков и решение целиком.

## Последствия

* Изменение порога: новая версия конфига аналитиком, пересборка golden-файла, обновление ожидаемых версии и хеша, перезапуск; код не меняется.
* Сохраненные вход и версии дают основание для воспроизведения расчета при наличии соответствующих конфигов. Это не доказательство полного воспроизведения внешнего банковского процесса.

## Граница управления политикой

Реализованы загрузка файлов, проверка версии и хеша, чтение параметров и JSON. Это не редактор и не governance policy: согласование, публикация, откат и сравнение экспериментов через UI не реализованы. Изменение существующих параметров возможно в конфиге; новые типы правил могут требовать кода и проверки.
