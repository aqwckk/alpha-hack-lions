# Веб-интерфейс: кабинет клиента и рабочее место банка

Одностраничное приложение (SPA) на React 18 + TypeScript (strict) + Vite. Через него проходит весь кредитный путь: подбор продукта, заявка, дозапрос, решение, подписание и выдача, а сотрудники банка ведут очередь, принимают решения и смотрят метрики. Карта экранов и связь с пользовательскими историями: [../docs/product/ui-guide.md](../docs/product/ui-guide.md).

## Запуск

| Что | Команда | Адрес |
|---|---|---|
| Вся система в Docker | `docker compose up --build -d` (из корня) | http://localhost:8080 |
| Только фронтенд в режиме разработки | `make web-install`, затем `make web-dev` (нужен запущенный api на :8000) | http://localhost:5173 |
| Проверки | `make web-test` (typecheck, тесты, сборка) | |
| Типы API из контракта | `make web-types` (после `make openapi`) | |

Node.js 22 или новее, зависимости ставятся строго по `package-lock.json` (`npm ci --ignore-scripts`). Версии в `package.json` зафиксированы без `^` и `~`.

Тестовые учетные записи показываются на странице входа, если бэкенд работает в демо-режиме (`DEMO_MODE=true`, флаг читается из `GET /api/v1/meta`). Клиенты: пароль `Demo-Client-2026`, андеррайтеры `Demo-Uw-2026`, риск-менеджер `Demo-Risk-2026`.

## Команды npm

| Скрипт | Назначение |
|---|---|
| `npm run dev` | Vite dev server, прокси `/api` на `http://localhost:8000` |
| `npm run build` | production-сборка в `dist/` (без source maps) |
| `npm run typecheck` | `tsc --noEmit`, отдельно от сборки |
| `npm test` | Vitest + Testing Library + MSW |
| `npm run gen:api` | `openapi-typescript ../docs/api/openapi.json -o src/shared/api/schema.d.ts` |

Сгенерированный `src/shared/api/schema.d.ts` хранится в репозитории: образ собирается без доступа к `docs/`. После изменения API выполните `make openapi` и `make web-types`, затем `npm run typecheck` покажет расхождения.

## Переменные окружения

Секретов и `VITE_*` переменных у фронтенда нет: браузер всегда обращается к тому же origin (`/api`). Настраивается только окружение запуска:

| Где | Переменная | По умолчанию | Смысл |
|---|---|---|---|
| docker compose | `WEB_PORT` | `8080` | порт, на котором открывается интерфейс |
| `vite.config.ts` | `apiTarget` | `http://localhost:8000` | куда dev server проксирует `/api` |

## Структура

```text
web/

  nginx/                   nginx.conf, сервер SPA, заголовки безопасности
  src/
    app/                   провайдеры, маршруты, тема, глобальные стили
    shared/api/            HTTP-клиент (openapi-fetch), сессия, ошибки, ключи запросов, команды
    shared/lib/            форматирование денег и дат, проверка ИНН, словари подписей, глоссарий
    shared/ui/             общие компоненты: статусы, состояния загрузки и ошибок, подсказки к терминам
    features/auth/         вход, восстановление сессии, защита маршрутов по роли
    features/layout/       шапка, меню, уведомления
    features/client/       мои заявки, подбор, мастер заявки, статус, дозапрос, решение, подписание
    features/bank/         очередь, карточка заявки, диалоги решений
    features/risk/         метрики, версии скоринга и политики, аудит
    features/demo/         подсказки демо-режима и панель симулятора
```

Тяжелые разделы (рабочее место банка, графики Recharts) загружаются отдельными чанками: клиент их не скачивает.

## Как устроена работа с API

* **Сессия.** Access-токен живет только в памяти модуля `shared/api/client.ts`. После перезагрузки страницы сессия восстанавливается через `POST /api/v1/auth/refresh` (HttpOnly cookie, JavaScript ее не видит). Одновременные обновления схлопываются в один запрос, между вкладками сериализуются через Web Locks: refresh-токен одноразовый. На `401` запрос повторяется один раз после обновления, если обновить нельзя, пользователь попадает на вход с сообщением "Сессия истекла".
* **Команды.** Кнопки действий строятся только из `available_actions`. Каждая команда передает `expected_version` из последнего ответа и новый `Idempotency-Key` на каждое нажатие; автоматический повтор после сетевой ошибки идет с тем же ключом. Повторный клик во время запроса игнорируется.
* **Ошибки.** Один класс `ApiError`: `409 VERSION_CONFLICT` перечитывает заявку и объясняет, что данные обновились; `422` раскладывается по полям формы со ссылками "Исправить"; `SIGNING_CODE_INVALID` показывает оставшиеся попытки; `409 ALREADY_TAKEN` называет коллегу, который взял заявку; `403` и `404` показываются как "не найдено или нет доступа". Нет связи: баннер "Нет связи с сервером, повторяем..." и автоматический повтор чтений.
* **Живой статус.** Заявка клиента опрашивается каждые 3 секунды в статусах `SENT`, `CHECKING`, `DOCUMENTS`, `PAYOUT` и каждые 15 секунд в остальных нетерминальных; уведомления раз в 15 секунд и сразу при смене статуса. Ответ команды не может быть перезаписан более старым ответом опроса (сравнение `version`). Карточка сотрудника не опрашивается: каждое ее чтение пишется в аудит.
* **Черновик.** Мастер заявки сохраняет только измененные поля (`PATCH`) через 1,5 секунды после ввода, при уходе с поля и при переходе между шагами; индикатор "Сохранено в 14:32". Конфликт версии перечитывает заявку и повторяет сохранение.

## Безопасность

* CSP без `unsafe-inline` для скриптов: `script-src 'self'`; стили допускают inline (Mantine задает CSS-переменные), `frame-ancestors 'none'`, `object-src 'none'`, `connect-src 'self'`. Также `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy: no-referrer`, `Permissions-Policy`.
* Заголовки ставятся только для SPA: ответы `/api` (включая Swagger UI) идут с заголовками самого API.
* Нет `dangerouslySetInnerHTML`, сторонних скриптов, аналитики и service worker. Токены не попадают в `localStorage`, ИНН не попадает в URL.
* Возврат после входа разрешен только на маршруты своей роли (защита от open redirect).
* nginx работает от пользователя `nginx`, файловая система контейнера только для чтения, временные файлы в `/tmp`.
